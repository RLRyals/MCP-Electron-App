# FictionLab Workflow Execution

This skill connects to the FictionLab app to execute writing workflows.

**IMPORTANT**: The FictionLab app MUST be running before using this skill.

## How to Use This Skill

When the user asks to list, execute, or get workflow information, use the commands below.

### List all available workflows

```bash
node ipc-client.js list
```

Run this when the user asks "what workflows are available" or "list my workflows".

### Get workflow details

```bash
node ipc-client.js get WORKFLOW_ID
```

Replace `WORKFLOW_ID` with the actual workflow ID from the list command.

### Execute a workflow

```bash
node ipc-client.js execute WORKFLOW_ID
```

Replace `WORKFLOW_ID` with the workflow ID.

**With options:**
```bash
node ipc-client.js execute WORKFLOW_ID --workspace "/path/to/project" --variables '{"genre":"Urban Fantasy"}'
```

## Common Workflow IDs

These are typical workflows users might ask for:

- `series-architect-orchestrator` - Complete 6-stage series planning pipeline
- `series-architect-intake` - Stage 1: Intake and assessment
- `series-architect-research` - Stage 2: Market research and genre pack
- `series-architect-framework` - Stage 3: Series bible and framework
- `simple-test-2` - Simple test workflow (use this to verify connection)
- `idea-to-series-2` - Transform book idea into 5-book series

## Error Handling

If you get "FictionLab is not running" error, tell the user:

1. Launch the FictionLab application
2. Check that Docker containers are running (Services tab should show green status)
3. Verify the Workflow plugin is active in the Plugins tab
4. Try the command again

## Expected Output

When a workflow completes, you'll see:
- ✅ Success status with instance ID
- List of completed workflow nodes
- Output variables generated by the workflow

When a workflow fails:
- ❌ Failed status
- Which node failed
- Error message

Present this information clearly to the user.

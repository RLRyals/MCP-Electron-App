# FictionLab Workflow Execution

Execute multi-phase writing workflows directly from Claude Desktop. This skill connects to the FictionLab app running on your computer to execute workflows for series planning, book structuring, chapter writing, and quality gates.

## Prerequisites

**IMPORTANT**: FictionLab app MUST be running before using this skill.

1. Launch FictionLab app
2. Verify Docker services are running (Services tab)
3. Verify Workflow plugin is active (Plugins tab)
4. You should see: `[IDE IPC Server] Listening on \\.\pipe\fictionlab-workflow-runner` (Windows) or `/tmp/fictionlab-workflow-runner.sock` (Mac)

## How to Use

### List Available Workflows

To see all workflows available in FictionLab:

```
/fictionlab-workflow list
```

### Execute a Workflow

To execute a specific workflow:

```
/fictionlab-workflow execute <workflow-id>
```

Example:
```
/fictionlab-workflow execute 12-phase-novel-pipeline
```

### Get Workflow Details

To view a workflow's definition:

```
/fictionlab-workflow get <workflow-id>
```

## Common Workflows

### Series Planning
```
/fictionlab-workflow execute series-architecture-v2
```

### Book Structure
```
/fictionlab-workflow execute book-structure-12-phase
```

### Chapter Writing
```
/fictionlab-workflow execute chapter-writing-pipeline
```

### Quality Gates
```
/fictionlab-workflow execute npe-validation-gate
```

## Advanced Options

You can pass optional parameters when executing workflows:

- **Workspace**: Specify project directory
- **Variables**: Pass initial workflow variables

Example with all options:
```
/fictionlab-workflow execute 12-phase-novel-pipeline \
  --workspace "C:/Users/Author/Documents/MyNovel" \
  --variables '{"genre":"Urban Fantasy","targetWordCount":80000}'
```

## Troubleshooting

### "FictionLab is not running" Error

This means the IPC connection failed. Check:

1. FictionLab app is open and running
2. Services tab shows Docker containers as "Running"
3. Plugins tab shows Workflow plugin as active
4. Console output shows IPC server started

### Connection Timeout

If workflows take too long:

1. Check Docker containers are healthy
2. Verify PostgreSQL connection in FictionLab
3. Check workflow complexity (some workflows take 5-10 minutes)

### Platform-Specific Notes

**Windows:**
- Uses named pipe: `\\.\pipe\fictionlab-workflow-runner`
- Path format: `C:/Users/...` or `C:\Users\...`

**Mac:**
- Uses Unix socket: `/tmp/fictionlab-workflow-runner.sock`
- Path format: `/Users/...`

## Workflow Results

When a workflow completes, you'll receive:

- **Instance ID**: Unique execution identifier
- **Status**: success or failed
- **Completed Nodes**: List of workflow steps completed
- **Output Variables**: Data generated by the workflow
- **Failed Node**: If failed, which step caused the failure

Use these results to understand what the workflow accomplished and troubleshoot any issues.

## Security

This skill only communicates with FictionLab running locally on your machine via IPC socket. No external network connections are made. All workflow data stays on your computer.

What Gets Installed

FictionLab's core promise: set up Docker, the database, and the local TypingMind MCP Connector container — with zero plugins installed. Plugins (workflow, kanban, …) add capability on top of that core; they are never required for the app to install, boot, and be usable.

Source of truth: docs/CORE-VS-OPTIONAL-COMPONENTS.md in the app repo, checked against docker-compose.yml and enforced in CI by e2e/pluginless.spec.ts. This page mirrors that document; if the two ever disagree, the doc in the repo is canonical.

Core (bare install — no plugins)

Everything below installs and starts with zero plugins present.

ComponentContainer nameRole
PostgreSQL fictionlab-postgres Primary datastore for the app and all MCP servers
PgBouncer fictionlab-pgbouncer Connection pooling in front of PostgreSQL
MCP Writing Servers fictionlab-mcp-servers The set of MCP servers (DB admin, NPE, workflow manager, outline, kanban, etc.) that the connector fronts
MCP Connector fictionlab-mcp-connector The local TypingMind MCP Connector (@typingmind/mcp), listening on :50880, that bridges MCP clients to the writing servers — the Docker container the app orchestrates, not TypingMind's cloud connector

Core app surfaces that must always be reachable with zero plugins installed:

  • Dashboard — Running/Next/Blocked cockpit
  • Settings > Setup — the setup wizard (Docker/client detection, env config)
  • Settings > Database
  • Settings > Services — the container list above, with start/stop/restart controls and live status
  • Settings > Logs
  • Plugins — browse/install plugins from here; this is how a bare install gains optional capability
  • Help / About

Optional (added by plugins)

PluginAdds
fictionlab-workflow The Workflows nav view/tab (FictionLab workflow execution UI)
fictionlab-kanban The Kanban board view (plugin-owned since fictionlab-workflow 1.1.0's containment migration — the app no longer bundles this view; the plugin ships its own renderer bundle)

Plugins are discovered from your FictionLab user-data plugins folder and can be installed, updated, or removed at any time from the in-app Plugins screen — no reinstall of the app required.

Not part of any install

Development-side tooling used to build and track FictionLab itself — the beads issue tracker (bd), scheduled tasks, and background pollers used by the dev team — is never bundled, installed, or run by the app. If you install FictionLab, none of that ships to your machine.

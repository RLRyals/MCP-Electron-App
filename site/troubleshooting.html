Troubleshooting

Known failure modes, keyed by what you see in the app. Each entry tells you what is actually broken, how to confirm it, and the fix that works — including the tempting fixes that don't.

Boards, Workflows, and Database admin are all empty (Windows)

Symptom. FictionLab launches, but the Kanban board shows no boards, the Workflows view shows no workflows, and Settings > Database shows nothing — all three at once. Docker Desktop reports every container as running and healthy, and your data is still safely in the database.

What is actually broken. Docker Desktop's port-forwarding layer — the relay that carries connections from Windows localhost into the WSL2 containers — has silently died. The containers themselves are fine; checks run inside a container (docker exec) pass, because they bypass the relay. But every Windows-side process, including FictionLab, gets ECONNRESET when it connects to localhost:5432 / localhost:6432 (PostgreSQL / PgBouncer) or the MCP service ports. All three views die together because they share that one dependency.

What does NOT fix it. Restarting or rebuilding the containers, and relaunching the app. The fault is in Docker Desktop itself, not in anything it is running — this failure has been observed to survive two full container teardown/rebuilds and an app relaunch.

The fix — restart Docker Desktop completely, not the containers:

  1. Right-click the Docker whale in the system tray → Quit Docker Desktop, and wait for it to fully exit.
  2. In any terminal (PowerShell or CMD), run wsl --shutdown.
  3. Start Docker Desktop again and wait until it reports the engine is running.
  4. Relaunch FictionLab. Boards, workflows, and the database view come back on their own — no data is lost, because the database volume was never the problem.

Rebooting the whole machine also cures it (a reboot restarts Docker Desktop and WSL along with everything else), but it's the sledgehammer version — the three steps above fix it in under a minute without closing the rest of your work.

How to confirm this is your problem before restarting anything: in PowerShell, run Test-NetConnection localhost -Port 6432. If that fails or the connection resets while docker ps still shows fictionlab-postgres and fictionlab-pgbouncer as healthy, the relay is dead and the fix above applies.

Heads-up: wsl --shutdown stops everything running inside WSL2, not just Docker. On a typical FictionLab install only docker-desktop lives there, so nothing else is affected — but if you run Linux distros or other WSL workloads, save their state first.
